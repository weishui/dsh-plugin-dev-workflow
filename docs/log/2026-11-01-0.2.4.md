# 2026-11-01 · 0.2.4 工作区下拉修复版

0.2.3 发完当天追加：入口出现后，看板的工作区下拉恒为空——左侧明明有十几个工作区，
面板却永远停在「还没有打开的工作区」空态；用户打开项目后回到看板又被要求打开，
形成循环（负责人截图留证）。

## 根因

宿主 `@deepseek-ai/dsh-client-ui-workspace` 源码确认：`workspaces.list.getSnapshot()`
返回**对象** `{ items, pinnedSessionIds, archivedSessionIds }`（元素含
`path` / `title` / `workspaceId`），而看板 `client.js` 把快照当**数组**读：
`Array.isArray(snapshot)` 恒 false → 下拉恒空。0.2.3 的入口修复让面板终于能渲染，
这个形状不匹配才第一次暴露出来。

## 修复

`client.js` 增加 `workspaceItems()` 归一化：数组直接用、对象取 `items`，其余返回空。
下拉映射保持 `id = workspace.path`、`label = workspace.title || workspace.path`。

## 本轮踩坑

1. **UI 面板修好入口只是第一关**：能渲染 ≠ 能取数。宿主服务的快照形状必须在第一次
   面板渲染前对齐，否则空态文案会误导用户去「打开项目」——而列表恰恰来自用户已经
   打开的工作区，形成死循环。
2. **对照宿主源码取字段名**：`items` / `path` / `title` 都从
   `dsh-client-ui-workspace/lib/client.js` 真实读取（buildGroup 与 keysByPath 两处），
   不猜字段。
