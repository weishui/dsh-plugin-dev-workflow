## 新能力：dev_request_close

给需求三种终态：`delivered`（已交付）/ `invalid`（已作废）/ `superseded`（已被取代）。

- **append-only**：向 requests.jsonl 追加一行同 requestId 的状态记录，reader 按
  requestId 取 latest——不改写、不删除任何历史行。
- **看板**：需求列只陈列未终结需求；计数拆出 `openRequests` / `closedRequests`，
  「全部」= 全部唯一需求 + 全部任务；已完成过滤含已终结需求。
- **兼容**：旧宿主（无 openRequests 字段）走 client 侧回退分支，chips 仍然成立。

## 配套

- 运行期提醒的需求计数改为按 requestId 去重——否则每次 close 都会让「需求 N」膨胀。
- smoke：close 后需求列排除 + 计数断言 + unknown requestId 抛错 + latest 语义幂等；
  「全部」计数断言改为 counts.requests + counts.tasks（不再用窗口内条数）。
- README 工具箱与看板说明同步。

## 本轮踩坑

1. **窗口化断言别用窗口内条数算总量**：「全部」chip 以前等于 `payload.requests.length
   + payload.tasks.length`，需求列改成只陈列 open 之后，这个等式天然不成立——总量
   必须来自 counts 的全量字段。
2. **默认计数要跟着新记录形状走**：close 行追加进 requests.jsonl 后，按行数计数会
   把「需求 12」悄悄变成「需求 23」。凡是会追加状态行的文件，计数必须按 id 去重。
