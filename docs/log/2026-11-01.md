## 本轮踩坑

1. **"任务为 0 时不写业务文件"被提醒机制自己违反了一次**：先建了诊断任务又立刻开写，
   属实。教训是提醒文案有效但不自动生效——0.1.1 的 pre-step 注入解决的就是这个，
   本会话 47 次注入即证据。
2. **顶部计数语义变更**：从"列里渲染了几条"改成"日志里共有几条"，否则 200 需求项目
   会显示"全部 220"这种假数。如有依赖旧语义的下游需注意。
3. **npm OTP 无法代做**：`npm publish` 在无 TTY 下快速返回 EOTP（不挂起），凭据有效性
   可以用 `npm whoami` 单独验证，不必拿 publish 试错。
4. **截图即证据的做法**：`verify/preview.mjs` 用 `readBoard()` 真实数据 + client 同一套
   `collect()/columnNode()/CSS` 渲染，不是手画稿——三次视觉迭代都靠它闭环。
